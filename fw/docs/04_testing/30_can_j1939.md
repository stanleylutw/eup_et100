## 2. EVB 原理圖與 timing 證據

唯讀解析 `FR3068E-C_Device_DEV1.4.SchDoc` 的 OLE FileHeader records（非板上量測）：

- U3 comment `TJA1044GT/3Z`，owner 271，pin 8 名稱為舊符號 `RS`（位置 420,730，外端 430,730）。
- wire `JCWUGSCD`：430,730→460,730；R26 owner 417，10K，右端 480,730；wire `SFPQKIOH`：480,730→510,730→510,740，連 GND power port `BCXOJZUH`。因此 STB 經 R26 10 kΩ 下拉，EVB 不需額外 GPIO。此為設計證據，Stanley 仍需確認實際裝配。
- J2 網標：PA10↔CAN_RX、PA11↔CAN_TX。程式設定 GPIOA10／11 AF5、CAN3。硬體跳線／終端／供電不能由 host 證實。

MCAN 選 D48M／2，SDK `system_get_peripheral_clock(PER_CLK_CANx)` 應為 24 MHz。套用時讀 SDK clock 並驗整除，非硬編未知時鐘：

| 速率 | Prescaler（實值） | NBTP NBRP | NTSEG1（實際） | NTSEG2（實際） | NSJW（實際） | sample point |
|---|---:|---:|---:|---:|---:|---:|
| 250 kbps | 4 | 3 | 19（20 TQ） | 2（3 TQ） | 2（3 TQ） | 21／24 = 87.5% |
| 500 kbps | 2 | 1 | 19（20 TQ） | 2（3 TQ） | 2（3 TQ） | 21／24 = 87.5% |

計算：24 MHz／prescaler／(1+20+3)。實際板上 clock／波形待測。CAN RAM 2056 bytes：一個 extended filter 8 B、FIFO0 64×16 B、SDK 固定保留未用 dedicated RX 64×16 B；無 TX buffer／queue。SDK 的 `can_init()` 會清 MON 並啟用 FD，本版不呼叫；新接合直接在 INIT／CCE 中設 timing／MON／classic，RAM setup 結束會退出 INIT，之後重新進 INIT 才寫 protected filter registers。MON 在 INIT／CCE 中設定，所有速率路徑始終不進 NORMAL。§5 修正移除重複呼叫 SDK monitoring helper，並確認 INIT 已退出才回成功。

Stanley 已確認 PA10 波形，並明確要求「please use dap to debug it」。以 pyOCD 0.36.0、DAP-Link-II `2024-2425-6285`、1 MHz、`connect_mode=attach`、`resume_on_disconnect=false`、`auto_unlock=false` 連接。全程 CPU RUNNING，未 halt／reset／燒錄／寫 peripheral control；CoreSight 必需的 attach 由 pyOCD 完成。PSR 為最後單次讀取（可能更新硬體診斷讀取狀態），沒有清 IR／FIFO ACK。比對當時板上 `can3_line0_irq` 的 64 bytes 與修改前 ELF 完全一致，才解讀其 RAM diagnostics。三次取樣間隔 1 秒。

| 項目 | 實讀 |

| CCCR | `0x00000061`：INIT=1、CCE=0、MON=1、DAR=1、FD／BRS=0 |

**確定缺陷**：硬體 INIT=1，但軟體僅檢查 MON=1 就回成功並顯示 SYS12=2。INIT 未退出足以阻止正常接收；此狀態與全 F 樣本一致。舊路徑在 SDK RAM setup 退出 INIT 後立刻重進，最後退出 INIT 後又呼叫無等待的 `can_enter_bus_monitoring_mode()` 再次進出。這是需修正的時序風險；目前唯讀證據不能獨立證明是哪次請求造成 INIT 停留，或排除其他 clock／硬體問題。

**ET-100 接合層修正**：RAM setup 退出後先 bounded wait INIT=0，再進 INIT/CCE 設 filter；最後退出後同樣 bounded wait INIT=0，不再呼叫多餘 monitoring helper。只有 INIT=0、CCE=0、MON=1 且 FD／BRS=0 才回成功／啟用 NVIC。退出逾時回失敗，SYS12=6，由既有 500 ms 重試機制處理，保持監聽模式。F407 模組與 SDK 原檔均未改。
